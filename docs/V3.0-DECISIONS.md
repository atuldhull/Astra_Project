# ASTRA v3.0 — Architecture Decisions

Locked at the start of the v3.0 sprint. Each decision is binding for the
duration of the release. Changes require an explicit ADR amendment.

| #     | Decision                                                                                       | Rationale                                                                          |
| ----- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| AD-1  | Tag is `v3.0.0-sovereign`. Branch is `release/3.0`.                                            | Clean cut from R3 (`v0.3.0-round3`).                                               |
| AD-2  | Every Tier 1 + Tier 2 feature ships behind an env flag, default ON in dev, configurable in prod. | One env var = instant rollback. Survives demo-day surprises.                       |
| AD-3  | Migrations are forward-only, additive. No DROP, no destructive ALTER TABLE.                    | If demo breaks, last-known-good DB is recoverable without rollback ceremony.       |
| AD-4  | E2E regression must pass after every Tier 0 / Tier 1 feature.                                  | Catch compounding bugs early.                                                      |
| AD-5  | One feature per branch off `release/3.0`, fast-forward merged after green.                     | Bisectable history, every feature isolatable.                                      |
| AD-6  | Every feature commit message ends with a "Demo line:" describing user-visible value.           | Forces clarity. Slide bullets write themselves.                                    |
| AD-7  | `ASTRA_FORCE_R3=true` env var degrades any v3.0 feature to its R3 behaviour.                   | Demo-day escape hatch.                                                             |
| AD-8  | Feature flags are TTL'd: any flag still on/off-by-default 30 days post-`v3.0.0` final is removed (either path). | Avoid permanent technical debt.                                                    |
| AD-9  | No feature merges without a Definition of Done captured in `RELEASE-V3.0.md`.                  | Prevents "is it actually done?" debates.                                           |
| AD-10 | GPU-blocked tasks (PGD, MAR20 federated, TensorRT) must finish ≥ 24h before any judged demo.   | Buffer for retraining if A/B fails.                                                |

## Code-style rules (binding for v3.0)

1. Files under 500 lines. Refactor before crossing.
2. Every endpoint has Pydantic typing. Every component has prop types.
3. Every `useEffect` returns a cleanup or has `// eslint-disable-next-line` with a reason.
4. No `console.log`, no commented-out code, no `TODO` without a corresponding line in `docs/V3.0-TODO.md`.
5. New code goes in new modules unless the touched file is < 200 lines.
6. Backend module imports are alphabetised, frontend imports are grouped (lib → components → pages).
7. No new dependencies without justification in commit message.

## Testing minimum bar

- `scripts/e2e_regression.py` ALL GREEN after every commit on `release/3.0`.
- `npx tsc --noEmit` clean from `frontend/`.
- Manual smoke on the touched page after every UI change.

## Release cadence

- `v3.0.0-rc1` end of Day 1
- `v3.0.0-rc2` end of Day 2
- ...
- `v3.0.0-sovereign` end of Day 7

Each `rc` tag implies: e2e green, latency captured, manual smoke clean,
day's commits squashed-to-readable, day summary written to `docs/V3.0-DAYLOG.md`.
